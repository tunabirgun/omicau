Release v0.4.0

Multi-omics benchmarking with explicit safeguards

omicau evaluates multi-omics predictive workflows and records the evidence needed to interpret their results. It is intended for research benchmarking, not clinical decision-making.

Quick start Suite DOI GitHub
Frozen benchmark suite The pre-execution protocol and executable suite are archived at doi:10.5281/zenodo.22304152. The archive excludes benchmark results, raw data, local paths, and caches.

Completed benchmark summary

The completed v0.4.0 run recorded 13,507 of 13,507 registered units with zero failures across binary and continuous synthetic families, five internal cohorts, and a 27-unit exploratory CPTAC analysis. The aggregate results are prepared for the companion article and are distinct from the frozen pre-execution archive. The CPTAC analysis is exploratory and is not used to support a general superiority claim.

Safeguards

Safeguards were evaluated under null and injected conditions in both synthetic families. Each required gate method produced zero false alarms across 40 null cases and recovered all 40 injected cases in both families. Supplemental DIABLO produced 0/40 and 40/40 in its eligible binary family; supplemental block-PLS produced 0/40 false alarms and 33/40 detections in the continuous family.

  • Required-method null checks: 0 / 40 false alarms in both families.
  • Required-method injected checks: 40 / 40 detections in both families.
  • Interpretation: read performance estimates together with the recorded safeguard outcomes and cohort context.

Quick start

Install the exact release, create the bundled synthetic example, run it, verify its provenance, and inspect the resulting report.

python -m pip install "omicau==0.4.0"
omicau bootstrap --dataset mock --out-dir demo
omicau run --config demo/config.json --cores 8
omicau verify --config demo/config.json --audit demo/run/audit.json

Open demo/run/report.html after the run. Choose a core count appropriate to the available memory and workload.

Inputs and outputs

Provide one numeric matrix for each omics layer and a clinical table containing the endpoint. Include a group identifier when related samples must remain in the same evaluation split, and a batch variable when it is available.

InputPurpose
Omics matricesNumeric features for each assayed layer
Clinical tableSample identifier, endpoint, and optional group and batch columns
Configuration filePaths, endpoint definition, evaluation settings, and output location

Each run writes an interactive report.html, machine-readable audit.json, and tabular exports including model metrics and modality-level results. Use the configuration and run outputs together when reproducing an analysis.

Reproducibility and public mapping

The Zenodo DOI identifies the frozen protocol and executable suite, not a completed-results deposit. Subsequent byte-level release mapping found that all 73 submitted source files matched the PyPI source distribution and all 47 implementation files matched across the source distribution, wheel, and v0.4.0 release tag. The exact PyPI source distribution passed 244 software tests; these tests establish defined behavior and failure handling, not biological or clinical validity.

Research-use limitation

Research use only omicau is not a diagnostic device. It does not diagnose disease, recommend treatment, or determine an individual’s risk. Do not use its outputs for clinical decisions.

Benchmark findings are conditional on the evaluated cohorts, data, comparators, and safeguards. A predictive result should be interpreted as cohort-specific evidence, not a claim of general clinical utility or method superiority.
